## 1. 목적

재앰핑용 학습 신호를 녹음하지 않고, **상업 음원 하나와 기타 세션 정보만으로** NAM에서 바로 쓸 수 있는 `.nam` 파일을 만든다.

기존 NAM 캡처는 같은 신호의 DI와 앰프 출력을 샘플 단위로 맞춘 페어로 학습한다. 음원에는 앰프 출력만 있고 DI가 없으므로, 이 프로젝트는 비페어(unpaired) 조건에서 톤을 추정하는 문제를 푼다.

### 1.1 결과물

1. 발표 자료
2. 시연: Gradio 앱으로 톤 찾기 과정을 보여 주고, 미리 녹음한 DI 리프에 생성된 `.nam`을 DAW에서 적용해 원곡 스템과 비교
3. GitHub 저장소: 코드, 실험 노트북, 시연용 실행 기록

보고서는 보류한다.

## 3. 전체 구조

```
[음원 파일] ─▶ ① 분리·구간 선택 ─▶ 기타 스템 구간 ─────────────┐
[곡 링크] ─▶ ②-0 LLM 장비 조사(선택) ─▶ 사용자 확인 ─┐          │
                                                    ▼          ▼
                          [세션 JSON] ─▶ ② 세션 처리 ─▶ 사전분포 + 세션 벡터
                                                    │          │
                                                    ▼          ▼
                                          ⑤ 인코더 ─▶ θ̂ ─▶ ⑥ 곡별 미세조정 ─▶ θ*, 후보들
                                                                         │
                                                                         ▼
                                                     ⑦ 증류: G(·; θ*) ─▶ model.nam

학습 단계(한 번): ③ G + ④ 합성 데이터 ─▶ ⑤ 인코더 학습
평가: ⑨
```

모듈끼리는 파일(wav, json, 체크포인트, .nam)로만 주고받아서 각각 따로 테스트할 수 있게 한다.

핵심 개념은 두 단계다. ⑥에서는 원곡 DI 없이 통계만 비교해 G의 설정 θ*를 찾는다. ⑦에서는 θ*를 넣은 G를 가상 앰프로 삼아 NAM 표준 입력을 재앰핑하고, 이 완벽한 페어로 NAM을 학습한다. NAM은 G(θ*)를 흉내 내므로 최종 품질의 상한은 G의 표현력과 ⑥의 정확도로 정해진다.

## 4. 모듈 설계

### 4.1 ① 분리와 구간 선택

**처리 순서**

1. 음원을 Demucs `htdemucs_6s`로 분리해 스테레오 기타 스템을 얻는다. 리드와 리듬 기타는 하나의 스템에 함께 들어간다.
2. 짧은 구간 단위로 좌우 상관도와 Side/Mid 에너지 비를 계산해, 기타가 한 대일 가능성이 높은 구간을 파형 위에 추천 표시한다. 판정은 참고용이다.
3. `capture_target`(rhythm/lead)에 맞는 안내 문구를 보여 준다.
4. 사용자가 미리 들어 보며 시작·끝 시간으로 구간을 여러 개 고른다.
5. 자동 점검: 무음을 뺀 연주 길이 합계(기본 15초 이상), 무음 프레임 제거, 클리핑 경고, 여러 대 섞임 경고. `same_rig`가 true이면 섞임 경고를 약하게 띄운다.
6. 짧은 크로스페이드로 이어 붙여 48kHz 모노로 저장한다.

**좋은 구간의 조건**: 기타가 한 대만 나옴, 다른 악기가 적음, 구간 안에서 톤이 같음, 피킹 세기가 다양함.

**대체 경로**: 기타 한 대 구간이 없으면 전체 스템을 쓰고 결과에 "여러 기타가 섞인 평균 톤"이라고 표시한다.

**출력**: `stem.wav`, `segments.json`

```json
{"song": "...", "segments": [[42.0, 58.5], [131.2, 140.0]],
 "active_sec": 22.4, "warnings": ["multi_guitar_suspected"]}
```

### 4.2 ②-0 LLM 장비 조사 (선택)

1. 곡 링크의 제목 정보에서 아티스트와 곡명을 뽑고 사용자가 확인한다. 링크에서 오디오를 내려받지 않는다. 분석할 오디오는 사용자가 파일로 올린다.
2. LLM과 웹 검색으로 두 단계 조사: 곡에서 쓴 장비, 아티스트가 평소 쓰는 장비. 곡 단위 정보에 출처가 있으면 우선한다. 평소 장비로 채운 필드는 확신도를 낮게(예: 0.5) 매긴다.
3. 출력은 4.3의 스키마와 같은 선택지 값만 허용하고, 필드마다 출처 URL과 확신도를 받는다. 출처가 없는 필드는 `unknown`.
4. 사용자가 출처와 함께 초안을 보고 수정·승인한다. 확정한 필드의 확신도는 1.0으로 바꾼다.

**환각 대응**: 출처 없는 필드는 `unknown`, 선택지 밖 값은 검증에서 거부, 사용자 확인 필수.

**오류 처리**: API 실패나 시간 초과 시 직접 입력 폼으로 전환. 스키마에 안 맞으면 한 번 재요청하고, 또 실패하면 맞는 필드만 채운다.

사용할 LLM API는 구현 계획 단계에서 정한다.

### 4.3 ② 세션 처리와 대응표

**입력 스키마**

```json
{
  "artist": "...", "song": "...",
  "capture_target": "rhythm",
  "same_rig": true,
  "guitar": {"pickup": "humbucker"},
  "amp":    {"family": "british", "model": "JCM800", "gain": "high"},
  "cab":    {"size": "4x12"},
  "boost":  "ts",
  "confidence": {"amp": 1.0, "boost": 0.5}
}
```

| 필드 | 값 | 영향을 주는 θ |
|---|---|---|
| `capture_target` | rhythm / lead | ① 안내 문구 |
| `same_rig` | true / false | ① 섞임 경고 강도 |
| `guitar.pickup` | single / p90 / humbucker / unknown | 입력 게인, 입력 하이패스 |
| `amp.family` | fender / vox / british / american_hg / modern_hg / unknown | 프리앰프 게인, 톤스택, 파워앰프 |
| `amp.gain` | low / mid / high / unknown | 프리앰프 게인 범위 |
| `amp.model` | 자유 텍스트 | 기록용. 알려진 모델명은 family로 변환 |
| `cab.size` | 1x12 / 2x12 / 4x12 / unknown | 캐비닛 블록 |
| `boost` | none / ts / unknown | 부스터 블록 (none이면 드라이브 0 고정) |
| `confidence` | 필드별 0~1, 기본 1.0 | 범위를 좁히는 정도 |

**대응표**: 요소별로 θ의 어느 차원을 어느 범위로 좁히는지 적은 표. 앰프 계열 5개, 게인 3단계, 캐비닛 3종, 픽업 3종, 부스트 2종. 값은 일반적으로 알려진 앰프 계열별 특징을 바탕으로 한 초기 가정이며, 대표 설정을 G로 렌더링해 들어 보고 조정한다.

**사전분포 계산**

1. 24차원 모두 [0, 1]에서 시작한다.
2. 입력된 요소마다 대응표 범위를 적용한다. 여러 요소가 같은 차원을 건드리면 교집합을 쓰고, 교집합이 비면 합집합으로 넓히고 경고를 남긴다.
3. confidence가 1 미만이면 그만큼 전체 범위 쪽으로 넓힌다.
4. 차원마다 [하한, 상한]과 중심값을 출력한다.

**세션 벡터**: 필드별 `unknown` 포함 원-핫을 이어 붙인 21차원(픽업 4, 앰프 계열 6, 게인 4, 캐비닛 4, 부스트 3)에 confidence를 곱한다. 자유 텍스트는 모델에 넣지 않는다.

### 4.4 ③ 그레이박스 앰프 G(x; θ)

**규칙**: 48kHz 모노, PyTorch로 직접 구현, 배치 처리 지원. θ는 0~1 정규화 벡터(24차원)이고 블록 안에서 실제 단위로 바꾼다(주파수는 로그, 게인은 dB 선형).

| 블록 | 구성 | 파라미터 | 개수 |
|---|---|---|---|
| 입력단 | 하이패스 → 게인 | 하이패스 주파수(40~200Hz), 입력 게인(−12~+12dB) | 2 |
| 부스터/OD | 피킹 EQ → 드라이브 게인 → tanh → 레벨 | 미드 중심(500~1500Hz), 미드 게인(0~12dB), 드라이브(0~30dB), 출력 레벨 | 4 |
| 프리앰프 2단 | 단마다 게인 → DC 오프셋 → tanh → DC 제거 → 로우패스 | 단마다 게인(0~40dB), 비대칭(DC 오프셋), 로우패스(2~12kHz) | 6 |
| 톤스택 | 로우셸프 → 피킹 → 하이셸프 | 저역 게인, 미드 주파수, 미드 게인, 고역 게인(각 ±12dB) | 4 |
| 파워앰프 | 드라이브 게인 → tanh → 새그 → 하이셸프(프레즌스) | 드라이브(0~20dB), 새그 양, 프레즌스 | 3 |
| 캐비닛 | 하이패스 → 피킹(공진) → 로우패스 → 피킹(음수 게인, 노치) | 하이패스, 공진 피크, 로우패스(3~7kHz), 노치 주파수, 노치 깊이 | 5 |

출력 음량은 θ에 넣지 않고 스템 RMS에 맞춰 정규화한다.

**구현 결정**

1. biquad 계수는 오디오 EQ 쿡북(RBJ) 공식을 쓴다.
2. 학습 중 필터는 주파수 영역 FIR 근사(계수로 주파수 응답을 구해 FFT로 곱하기)로 계산한다. 순환 컨볼루션을 피하려고 FFT 길이를 충분히 크게 잡고 패딩한다.
3. 최종 렌더링(⑦)과 검증에서는 torchaudio `lfilter`(시간 영역)를 쓴다.
4. 새그는 엔벨로프 추적(지수 커널 FIR 근사) 결과로 게인을 줄인다.
5. 클리핑 블록의 2배 오버샘플링은 ⑥ 곡별 미세조정과 ⑦ 최종 렌더링에서 켠다. ⑥을 48kHz로 맞추면 하이게인에서 앨리어싱 때문에 ⑦(96kHz) 렌더링과 대역별로 수 dB 차이가 나서(2026-11-10 합성 DI 측정: 저역 +5.5dB, 6~16kHz −4.3dB) θ*가 ⑦에서 다른 소리를 낸다. ⑥은 FFT 필터를 쓰므로 2배 비용만 든다. ④ 합성 데이터와 ⑤ 인코더 학습은 속도 때문에 48kHz로 두고, 그 차이는 ⑥이 보정한다.
6. 차단 주파수와 Q의 범위는 나이퀴스트 근처와 극단적 Q를 피하도록 제한한다.

**대비책**: 2026-11-12까지 필터 테스트(7장)가 통과하지 않으면 NablAFx(MIT)의 필터 함수를 출처를 밝히고 가져온다.

### 4.5 ④ 합성 데이터 생성기

샘플 하나의 생성 과정:

1. 세션 필드 값을 무작위로 정하고 ②로 사전분포를 만든다. 샘플의 약 20%는 θ 전체 범위에서 뽑는다.
2. 사전분포 안에서 θ를 뽑는다.
3. 세션 벡터에 드롭아웃을 적용한다(필드를 일정 확률로 `unknown`, confidence를 무작위로 낮춤).
4. EGDB DI에서 3초를 잘라 입력 음량을 무작위로 바꾼다.
5. y = G(x; θ)를 렌더링한다.
6. pedalboard로 무작위 EQ, 컴프, 짧은 리버브 증강을 건다.

데이터는 학습 중 GPU에서 바로 만들고 저장하지 않는다.

**EGDB 분할** (곡 단위로 나누고, 서로 겹치지 않게 한다)

| 분할 | 용도 |
|---|---|
| train | ④ 합성 데이터 (⑤ 학습) |
| val | ⑤ 검증 |
| pool | ⑥ 곡별 미세조정의 DI 풀 |
| test | ⑨ 실험 1의 가짜 곡 생성과, 정답 G와 .nam을 비교할 때 넣는 새 DI. ⑦ 증류 확인용 DI |

### 4.6 ⑤ 인코더

```
스템 3초 → log-Mel(128 밴드) → CNN 4~6층 → Global Pooling → 오디오 벡터
세션 벡터(21) ─────────────────────────────────────────────┐
[오디오 벡터 ; 세션 벡터] → MLP → sigmoid → θ̂ (24)
```

- 손실: θ MSE + MR-STFT(G(x; θ̂) vs y)
- 실제 곡: 3초 창 여러 개의 θ̂ 중앙값
- 학습: Colab GPU에서 몇 시간 이내 목표. 넘으면 층 수나 Mel 크기를 줄인다.
- 역할: ⑥의 시작점과 정규화 기준. 인코더가 없어도 파이프라인은 동작한다.

**체크포인트**

- 위치: `checkpoints/encoder_<θ버전>_<날짜>.pt` (`.gitignore` 대상). Colab에서는 Google Drive에 저장한다.
- 내용: `state_dict`, 옵티마이저 상태와 스텝(이어서 학습용), 모델 설정(Mel 밴드 수, 층 수), `theta_version`, 검증 손실.
- 저장 주기: 일정 스텝마다 덮어쓰고, 검증 손실이 가장 낮은 것은 `_best`로 따로 둔다. 세션이 끊기면 마지막 체크포인트에서 이어서 학습한다.
- θ 버전: 4.4의 블록 구성이나 범위를 바꾸면 `theta_version`을 올린다. 불러올 때 G의 버전과 다르면 오류를 내고, 인코더 없이 사전분포 시작점으로 진행한다.
- 배포: 최종 `encoder_<θ버전>_best.pt`는 저장소에 커밋해 클론만으로 받게 한다(`.gitignore` 예외, 중간 체크포인트는 제외). 수십 MB를 넘으면 Release 첨부로 바꾼다. 사용자가 .nam을 만들 때 필요한 오디오는 아래와 같다.
  - DI 풀: EGDB 클립은 저장소·Release에 넣지 않고, 설치 스크립트가 EGDB 공식 Google Drive에서 `audio_DI`를 직접 내려받는다(`gdown`). EGDB README에는 사용 허락("feel free to use EGDB")만 있고 재배포 조건이 없기 때문이다. 내려받은 뒤 4.5의 분할 규칙대로 pool 클립을 고른다. Drive 다운로드가 막히면 EGDB 공식 링크를 안내해 직접 받게 한다.
  - NAM 표준 입력 wav: 파일 자체에 라이선스 표기가 없고(NAM 코드의 MIT는 저장소 소프트웨어 대상, wav는 Google Drive 별도 배포) 재배포하지 않는다. 설치 스크립트가 NAM 공식 문서에 걸린 Google Drive 링크에서 직접 내려받는다(`gdown`). 막히면 공식 문서 링크를 안내한다. 버전은 NAM 학습 코드가 자동 판별한다.

### 4.7 ⑥ 곡별 미세조정 (통계 손실)

**준비**

- 타깃: ①의 스템 구간(무음 제외)에서 통계를 한 번 계산해 둔다.
- DI 풀: EGDB pool 분할의 3초 클립 수십 개. 기본은 무작위 선택.

**통계 4종** (모두 크기 기반, 전체 음량 차이 제거)

1. 장기 평균 스펙트럼: 모든 프레임의 log-Mel 평균. 톤스택, 캐비닛, EQ를 반영한다.
2. 레벨별 스펙트럼: 프레임을 신호 내 음량 분위수로 4구간으로 나눈 구간별 평균 스펙트럼. 왜곡은 세게 칠수록 배음이 늘고 EQ는 세기와 무관하다는 차이로 게인과 EQ를 구분한다.
3. 레벨 구간별 스펙트럼 평탄도: 왜곡의 양을 나타낸다.
4. 다이내믹: 프레임별 크레스트 팩터의 평균과 분산, 프레임 음량 분포의 폭. 압축감을 나타낸다.

**손실**

```
L(θ) = Σ wₖ · L1(통계ₖ(G(DI; θ)), 통계ₖ(스템))
     + λ_prior · (사전분포 범위를 벗어난 거리)²
     + λ_enc · ‖θ − θ̂‖²        (인코더가 있을 때)
```

각 항은 시작점의 손실값으로 나눠 정규화하고 같은 가중치로 시작한다. 가중치와 λ는 합성 데이터로 조정한다. λ_prior는 작게 두어 세션 정보가 틀려도 음원 근거가 강하면 범위를 벗어날 수 있게 한다.

**최적화**

- θ = sigmoid(u)로 두고 u를 Adam으로 최적화한다.
- 매 스텝 DI 클립 8개를 렌더링해 통계를 계산한다.
- 수백~천 스텝, 손실 정체 시 종료.
- 시작점 여러 개(사전분포 중심, 사전분포 샘플 몇 개, 인코더 θ̂)를 한 배치로 병렬 최적화한다. 최저 손실을 θ*로 쓰고, 서로 다른 상위 결과를 (a) 후보로 쓴다. 후보끼리는 θ 거리로 중복을 제거한다.
- 손실이 NaN이 되거나 발산하면 최선 θ로 되돌리고 학습률을 낮춰 재시작한다.

**진단 출력**: 통계별 잔여 차이(예: 고역 부족)를 저장해 화면과 발표 자료에 쓴다.

**출력**: `theta_candidates.json`, `loss_curve.png`, `candidate_k.wav`

### 4.8 (b) 세션 정보만 쓰는 경로 (선택)

②의 사전분포 중심값(또는 샘플 몇 개)을 θ로 쓰고 ⑤⑥을 건너뛰어 ⑦로 간다. 결과에 "음원 분석 없이 장비 정보만으로 추정"이라고 표시한다. 대응표는 ②와 공유하므로 추가 작업은 분기와 표시, 비교 실험이다.

### 4.9 ⑦ 증류

1. θ*를 G에 고정하고 `lfilter`와 2배 오버샘플링을 켠다.
2. NAM 표준 학습 입력 파일을 G에 통과시켜 output.wav를 만든다. 클리핑되지 않게 최대 레벨을 맞추고, 사용한 입력 레벨을 기록한다.
3. neural-amp-modeler로 학습한다. 지연 보정은 0. 학습 시간이 길면 더 가벼운 모델 크기를 쓴다.
4. `.nam` 메타데이터에 이름, 장비 정보, "음원에서 생성됨"을 기록한다.
5. 학습에 쓰지 않은 DI로 G와 .nam을 비교한다(ESR). 오차가 크면 경고하고 더 큰 모델로 재학습할 수 있게 한다.

생성된 .nam에는 캐비닛까지 포함되므로, 사용할 때 NAM 플러그인의 IR 로더는 끈다.

## 10. 한계

- 결과물은 앰프 하나가 아니라 마이크, 룸, 믹스 처리까지 포함한 "그 곡의 기타 톤" 캡처에 가깝다.
- 딜레이, 리버브 같은 공간계 효과는 담지 않는다.
- 표현력은 G의 블록 구조에 묶인다. 퍼즈, 옥타버, 모듈레이션은 다루지 않는다.
- 정확도는 실제 앰프를 재앰핑한 일반 캡처보다 낮을 것으로 예상한다. 장점은 녹음 과정 없이 만든다는 편의성이다.
- 정량 평가는 주로 합성 데이터에 기반한다.
- 대응표의 범위는 초기 가정이다.

## 11. 주요 결정 기록

| 결정 | 이유 |
|---|---|
| 접근법 C(그레이박스 + 인코더)를 중심으로 채택 | 한 달 미만, 1인 일정에서 끝까지 동작 가능, 해석 가능, 기능 2와 연결 |
| D(GAN) 대신 통계 손실 | GAN 학습 불안정과 디버깅 부담 |
| 스테레오 기반 분리 제외 | 곡마다 스테레오 구성이 달라 일반화 어려움 |
| 상용 분리 API 제외 | 유료, 외부 의존 |
| G 직접 구현 | 발표 질의 대응, 의존성 충돌 회피. 검증은 scipy 기준 테스트로 보완 |
| Google DDSP 미사용 | TensorFlow 기반, 앰프 블록 부재, 오래된 버전 고정 |
| 톤스택은 셸빙·피킹 필터, 캐비닛은 파라메트릭 필터 | 일정, 라이선스, 인코더가 맞히기 쉬운 파라미터 수 |
| ④⑤를 필수에 포함하되 ⑥ 경로를 먼저 완성 | 성능과 발표의 핵심 AI 모델이지만 실패 위험을 분리 |
| 시연은 녹음된 DI 리프를 DAW에서 재생 | 현장 연주 변수 제거, 같은 리프로 원곡과 직접 비교 |
| 인코더 체크포인트에 θ 버전 기록, 최종본은 저장소에 커밋 | 다른 사람이 재학습 없이 사용, G 변경 시 잘못된 가중치 사용 방지 |
| EGDB·NAM 표준 입력은 재배포하지 않고 공식 경로에서 내려받게 함 | 두 파일 모두 재배포 조건이 명시되지 않음. 사용자 편의는 같고 라이선스 문제가 없음 |
